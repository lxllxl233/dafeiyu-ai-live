## 1. 现象与根因

用户原话：「界面现在看不到弹窗」。

**根因不是 UI、不是 SSE、不是透明度：主播窗进程根本不存在。**

证据（问进程表，不问感觉）：

```
Get-CimInstance Win32_Process -Filter "Name='python.exe'"
 12000 run_engine.py
 24240 MamboTTS …\api.py -a 127.0.0.1 -p 9880
 23216 overlay_server.py            ← 弹幕服务在
 41748 overlay_server.py (:8791)    ← 残留
（没有 streamer.py / pythonw.exe）
```

- `streamer.py` 是**唯一**的屏上气泡窗口（`overlay/index.html` 那一路在 OBS 浏览器源里，
  观众看到的是它；屏上这块是给主播自己看的）。
- `Event Log`（Application，近 4 小时）里**没有** pythonw 崩溃记录 → 不是崩溃，
  是窗口被关掉了（`Ctrl+Alt+Q` / ☰→关闭），或被「只重启引擎」的脚本漏掉。
- 没有任何看护在跑：`tools/live.py watch`（心跳超时自动重启）当时**没有进程**在跑，
  所以窗口没了也没人管。

## 2. 关键坑：截图永远拍不到这个窗（差点误判成「窗口画不出来」）

排查中先做了两件事，都指向「窗口在但画不出东西」，**都是假信号**：

| 做法 | 结果 | 真相 |
|---|---|---|
| `CopyFromScreen` 抓窗口矩形 | 只有游戏背景，无气泡 | 窗口带 `WDA_EXCLUDEFROMCAPTURE`（"录屏里隐藏"），**抓屏 API 拍不到它**，不是没画 |
| `tools/shot_window.py --pid` | 同上 | 同上 |

真实判据只有一个：**问窗口自己要位图**——`PrintWindow(hwnd, hdc, 2 /*PW_RENDERFULLCONTENT*/)`
拿它自己的分层位图，数不透明像素。同一时刻的探针结果：

```
{"ok": true, "pid": 11440, "box": [2559,147,1363,300], "opaque_px": 408900}
```

位图里清清楚楚是「思考中……」气泡 + 头像 + `铁甲战士·A10 第3层·HP 52/80·金币 106`。
→ 窗口本来就会画，**只是那个进程当时不存在**。

## 3. 改了什么

| 文件 | 改动 | 为什么 |
|---|---|---|
| `tools/shot_popup.py`（新） | 主播窗像素探针：按心跳 pid 找窗 → `PrintWindow` 取位图 → 数不透明像素；`--quiet` 一行结论，`--out` 存图 | 没有它就无法在「不打扰用户」的前提下证明弹窗真在画；抓屏被判据排除 |
| `tools/live.py` `check_streamer()` | 心跳/进程都 OK 后再跑像素探针；探针失败或全透明 → `WARN 主播窗 pid X，心跳…，但窗口在但没画出东西` | 「进程活着」≠「屏幕上有气泡」，补一条**真实信号**，不是定时器 |
| `tools/live.py` `restart-streamer` / `watch` | 自愈起窗改成照抄用户配置：默认加 `--click-through`，`--capture` 默认关（新增 `--no-click-through`） | 旧默认会重启出一个「挡住鼠标、不穿透」的窗——自愈完用户还得手动改，等于没修好 |

没有加任何「N 秒后自动显示」的假逻辑；状态与可见性全部来自真实信号（心跳、位图像素）。

## 5. 还剩什么坑

1. **看护是要人起的**：`live.py watch` 不在任何自启动里，机器重启/手动关掉后要重开。
   开播前建议固定跑一次 `python tools/live.py check`。
2. **OBS 浏览器源里的旧字幕**：排查时看到直播姬预览里还挂着上一局的旧台词
   （「…目前最好成绩第二层boss」）。那是页面缓存 + 预览可能停帧，不是本次根因；
   换局时仍按老规矩 `POST /reset` 或刷新 OBS 浏览器源。
3. **`--capture` 与 `--click-through` 是两件事**：前者决定录屏/显示器捕获能不能拍到，
   后者决定鼠标能不能穿过去。自愈默认「穿透开、不参与录制」，与用户配置一致；
   要用直播姬显示器捕获拍弹窗时得显式 `--capture`。
4. `logs/streamer.lock`、`logs/run94_review.md` 仍是历史未跟踪文件，本轮没动。
