## 6. 新缺陷（run87 必修，按严重度）

### P10 · 牌组上限的「奖励界面死锁」（本局把牌组从 16 养到 21）

`sts2.py:2591 pending_card_reward()` 用「奖励列表里有未领的 Card」当判据；但引擎在玩家**主动跳过之后**
仍返回 `{"pending_card_choice": false, "can_proceed": true, "rewards":[{"reward_type":"Card","claimable":true}]}`，
于是 `collect/resolve` 被 `DECK_CAP` 永久拦住 → **每场战斗强制 +1 张牌**。
本局路径：f9(16→17) / f12(→18) / f14(→19) / f15(→20) / f21(+岩石铠甲 →19) / f22(+狂怒 →21)。
**修法**：判据改成 `reward.pending_card_choice == true`。
**叠加因素**：Pael's Tooth（每场战斗结束返还 1 张升级牌）让商店删到 16 的牌组又一路长回来 —— 报告里必须单列。

### P11 · 「生命损失/单次伤害上限」类机制没进斩杀线与 approx

- `硬化外壳20`（SKULKING_COLONY，f15 t4）：`calc.dmg 57 / lethal:[0]`，实际这一回合最多掉 20 →
  护栏「有全斩线」是**误报**；我用 `allow_no_lethal:1` 覆盖，改打 16 伤 + 12 甲（take 12 命中）。
- `难以杀灭9`（EXOSKELETON，f21 t3）：`lethal:[0,1,2]`，实际 27 血那只**打不死**（9+9=18）。
- **修法**：`sim.py` 给敌人加 `hp_loss_cap`（从 `b`/`bd` 的 `硬化外壳NN`）与 `dmg_cap`
  （从 `难以杀灭NN`），`lethal`/`dmg` 按 cap 计；两者都写进 `calc.approx`。

### P12 · `accuracy.py` 斩杀对账按下标 → 同批次先死后误报

见 §3.2：5 个假斩杀里 4 个是下标前移造成的。**修法**：按实体 id 或「本批次新死的 id 集合」对账；
逃跑（`ESCAPE_ARTIST`）应排除出「未预测死亡」。

### P13 · 逃跑被算成死亡 / 战斗结束回血被算成入伤

`f19 t5`：草蜢逃跑 + 燃烧之血 +6 → 同时污染「斩杀·未预测死亡」和「入伤 ±1」两项。
**修法**：`ended` 且 `clear` 的回合、以及`逃跑`事件，进 accuracy 时单独归类。

### P14 · 清场后追加尾牌 → `batch_error`

见 §3.1（f21 t4）。**修法**：`act.py` 在本批预计清场时截断 `seq`，或对"清场后还有牌"给 advisory。

### P15 · 脆弱是否削格挡（仍未裁决）

f12 t2 复现了 run85 的同一现象：引擎按 5 甲结算，sim 按 ×0.75=3 甲。
**修法**：用一个专门的局面钉死（或在钉死前把脆弱回合全部标 `approx`）。
