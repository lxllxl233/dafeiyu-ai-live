# 历史场景回放与回归（tools/replay_audit.py）

目的：不用重开游戏，也能验证「规则注入 / 经验检索 / 动作模拟 / 回执与护栏」在**真实历史局面**上
是什么行为，并给出**可复算**的四个指标。所有数字都能回到 `logs/decisions.jsonl` 的某一 `ts`。

## 0. 数据源

`logs/decisions.jsonl` 每行是一次决策，自带：

| 字段 | 用途 |
|---|---|
| `state` | 决策当时的**原始** `/state`（不是摘要）：手牌实费、敌人意图、遗物、药水、地图节点 |
| `before` / `after` | 决策前后各一帧摘要（hp/敌人血量/能量/格挡/手牌数），做前后差分 |
| `steps` / `forecast` | 执行器当时的逐步预测（每张牌 `d/blk/e`）与整回合预测（`hp/take/kill/clear/approx/…`） |
| `outcome` | `executed / rejected_validate / rejected_guard / rejected_fx / rejected_clear_overflow / batch_error / …` |
| `input.allow`（v22 起） | 护栏豁免；**老行没有这个键**，回放时单独计数 |

规模：2092 行 / 36 局，其中战斗行 2088；本赛季（run96–run106）433 行。

## 1. 四个指标怎么算

### 1.1 规则命中率（`rules` 注入 + 条件触发）

- **注入**：`hard_rules.for_ctx()` 每次都给 5 条，回放里按行计数，正常必须是 **5.0 条/行**。
- **条件触发**：把规则文字翻成可判定的谓词（审计侧解读，见下表），命中一次算一次触发。
- **违规**：触发且历史牌序/选择违反了它 → 算一次违规。`决策违规率 = 违规 / 触发`。

| 规则 | 触发（applies） | 违规（violated） |
|---|---|---|
| `dmg` 小伤害必挡 | 该回合入伤 ≥15 | 预测净掉 ≥15 且**无斩杀**（写着"已喝药仍掉"就标出来：喝了还是掉，等于没救住） |
| `self` 自伤闸 | 自己 ≤40% 血且手握 血墙/放血/祭品/突破 | 这一手真的打了那张自伤牌 |
| `potion` Boss 不省药 | Boss 战首回合带 ≥1 瓶 | 整场战斗一瓶没喝 |
| `boss` Boss 前血线 | Boss 战首回合 | 进战时 <70% |
| `hp_entry` 血闸（单独计） | 精英/Boss 战首回合且血低于 60/70% | 进战了（**含事件/被推图等非自愿**，所以只记"反例"、不进违规率） |

### 1.2 无效动作次数

`outcome != executed` 的行数（含 `not_combat / missing_seq / stale_end` 这类格式错误）。
再按局拆，看是哪一层拦下的（校验/护栏/fx/溢出/批处理）。

### 1.3 执行器状态不一致

`forecast`（当时预测）与 `after`（实际落地）对账，只对**可比行**：
跳过 `clear`（清场后回血）、`approx`（未建模机制）、`revive`、`tick`（状态税）、
`draw_unknown`（抽牌后手牌未知）、`heal`（这一手反而回血）。
分类：`ok` 一致 / `conservative` 预测更惨（安全方向）/ `optimistic` 预测更好（**危险方向**）/
`death` 预测死且真死 / `death_missed` 预测死但活下来。

### 1.4 护栏回归（今天重放历史牌序）

对每行用**今天的** `validate_plan` + `forecast` + `_guards` + `fx_error` 重跑同一 `seq`：

- `历史执行今天被拒` = 误伤（必须为 0）；
- `历史被拒今天全放行` = 保护退化（必须为 0）；
- `护栏保持` = 历史被护栏/fx 拒、今天仍拒（应等于历史被拒数）；
- `今天新拦` = 历史执行、今天被拦且**该行有 allow 记录**（真·新增拦截）；
- `allow 未入账的疑漏` = 历史执行、今天被拦、但老行没记 allow → **不能断言护栏漏了**。

### 2.3 规则→计划：最后一公里（`--plans`）

规则进了 `ctx.rules`，但 `plans` 是 `sim.search` 打分排出来的，**打分里没有规则**。
回放本赛季「≤40% 血 + 手握自伤牌」的 23 行：

```
23 行可比：18 行的推荐线仍含自伤牌（12 行无替代线，6 行本来有不自伤的替代线）
```

6 条有替代线却仍把自伤牌排在 `best` 的（真·规则没进打分）：

| 局面 | 血 | 手里 | 今天 best | 替代线 |
|---|---|---|---|---|
| run97 21:44:23 | 15% | 血墙 | best/guard 含血墙 | maxdmg |
| run104 23:42:07 | 40% | 血墙 | best/guard/potion 含血墙 | maxdmg |
| run105 23:49:29 | 8% | 血墙 | best 含血墙（预测 6→3） | maxdmg |
| run105 23:49:38 | 8% | 血墙 | best 含血墙 | maxdmg |
| run105 23:49:47 | 4% | 血墙 | best/maxdmg/guard 含血墙 | potion |
| run105 23:50:12 | 4% | 血墙 | best/maxdmg 含血墙 | potion |

这正是 run105 的死法：6 血时 `best` 就是血墙，模型照着打，6→3→1→0。
所以 v22 在 `plans[]` 加了 `self/self_why` 标记、在 `warn` 加了 `SELF_HP` 一行，
让冲突显式可见——**没有偷偷重排**（重排会藏掉「唯一能打的线」），裁决权留给模型。

### 2.4 怎么读这些数字

- **规则这一层过去根本没进过模型输入**（task 1 审计：skill 只加载过 3 次、压缩 20 次后掉出上下文），
  所以「历史违规率 27.8%」是**旧世界**的数字；现在的注入是 5.0 条/行（结构上不可能漏）。
  违规率本身不会因为注入而立刻下降——它要靠模型按规则改牌，这正是经验卡要解决的部分。
- **`potion` 68%（本赛季 6/6）**：Boss 战带药不喝是这季最稳定的"省药"失败，run96/run98 各一次，
  和 `docs/LESSONS.md` 里"Boss 不省药"对得上。
- **`self` 49%**：自伤闸触发时有一半仍然交了自伤牌，run105 的 6 血血墙是典型。
- **模拟 11.5% 不一致里"危险方向"43 条**是真正要盯的（预测比实际好 1–3 点），
  主要是覆甲/荆棘/易伤这类未建模小项；`death_missed` 7 条是预测必死却活下来（方向安全但说明模型偏保守）。
- **护栏回归 0 误伤 / 0 放行**：今天这套校验不会把历史正常牌序拦死，历史被拦的 15 条护栏 + 33 条 fx
  今天仍然全拦。9 条"疑漏"全部来自**老账本没记 allow**——已经补上（v22 起 `input.allow` 入账）。
- **规则→计划仍是缺口**：18/23 行的推荐线含自伤牌，其中 6 行有替代线。规则到了模型眼前，
  但 `sim.search` 的打分没算它；这是下一步该动的（给 `_score` 加自伤罚分，而不是继续加文字）。

### 2.5 胜率

**不比较**。到 2026-10-28 11:50 为止 mod 没在跑（`python sts2.py state` → `ConnectionRefusedError 10061`），
没有新局可跑；历史上是 **0 胜 / 9 败 / 2 中止**，样本也不足以谈胜率（见 `docs/EVALUATION.md`）。
回放能证明的是「输入与拦截变对了」，不能证明「会赢」。

## 3. 复现

```bash
python tools/replay_audit.py                        # 本赛季 433 行 + 今天重放
python tools/replay_audit.py --all --no-today       # 全部 2088 行，跳过重放（快）
python tools/replay_audit.py --runs 5UMKQR2A1K --show 20
python tools/replay_audit.py --plans                  # 再跑今天的 ctx：推荐线还含自伤牌吗
python tools/replay_audit.py --json logs/replay_audit_season.json
python tools/test_replay_audit.py                   # 判定函数自测（48 项）
```

产物：`logs/replay_audit_season.json`、`logs/replay_audit_all.json`（含每条违规/偏差的 `ts` 与数值）。

## 4. 已知局限（写清楚，别当成没问题）

1. `hp_entry` 只能证明「进战时血低于阈值」，不能证明「是玩家主动选的节点」——所以单列，不计入违规率。
2. 老行没有 `input.allow`，9 条「历史执行但今天被拦」无法区分「护栏漏」和「显式豁免」；
   v22 起已入账，下一季可精确判定。
3. 模拟对账用的是当时执行器的 `forecast`，不是今天重算的 `calc/plans`（重算要重跑搜索，慢且会和当时口径混）。
4. 经验命中按「今天的卡片库」回放，**当时并没有注入过**——这是"假如当时有这套检索"的覆盖率，不是历史行为。
5. 规则谓词是审计侧对规则文字的翻译，不是引擎行为；改规则文字要同步改 `rule_*` 函数和
   `tools/test_replay_audit.py`。
