# P1-2：计划可见性与覆盖

P1-2 不改变执行链，只把「本地搜索到底看到了什么」完整交给模型。目标是：
药水线不再被截掉、第 8 张手牌进入伤害上限、AOE/药水能进斩杀判断、
自杀线不再伪装成安全 `best`。

## 输出契约

`sim.search(state, max_cards=8, max_plans=5, time_limit=..., max_nodes=...)`
返回五类候选，每类最多一条：

| `k` | 含义 | 是否可能是自杀线 |
|---|---|---|
| `best` | 综合评分最高（伤害/掉血/能量/药水/击杀） | 只有全部候选都死时才会 |
| `maxdmg` | 纯伤害上限，不看防御 | 可能；`hp<=0` 时 `risk=True` |
| `kill` | 至少杀一只的线 | 可能换血过多 |
| `guard` | 本回合零掉血的线 | 否 |
| `potion` | 以药水开头的线，单独列出 | 否（但可能用掉药水） |

`ctx.plans` 不再 `[:3]` 截断，五类都输出；药水线始终单独一行。
`ctx.calc.dmg` 取所有候选（含 `maxdmg`）的最大伤害，因此第 8 张手牌的
伤害也能覆盖。

## 搜索边界

- 手牌最多看 **10 张**（原来 7 张）。
- `ctx` 深度 **8**（原来 6）；`max_cards` 上限 8。
- DFS 有**墙钟上限**（`ctx` 0.8s）与**节点上限**（120k）；超时只停止继续
  展开，已找到的候选照常返回，不抛异常、不阻塞出牌。
- 同 id/同费/同升级的等价排列仍然剪枝。

## 斩杀（`lethal_targets`）

现在按三种确定性顺序核对每个目标：

1. 易伤/力量/回能先手；
2. 纯伤害先手；
3. AOE 先手。

覆盖：

- 单体攻击；
- `aoe` 牌（对所有活怪结算，AOE 杀多只时每只都列出）；
- 伤害药水（单体/群体）；
- 力量、易伤、回能药水在伤害前使用；
- 目标格挡与易伤按 `Sim.hurt_enemy` 的同一套结算。

限制：这是**贪心核对**，不是完整 8 层 DFS。极端的「先打某张抽牌/变费牌
才能成立的斩杀」可能漏报；漏报只会少标 `calc.lethal`，不会把不能杀标成
能杀（所有结果都经过真实 `Sim` 结算）。

## 风险线

`plans[].risk`（ctx 里为 `1`）表示该线打完 `hp<=0`。`maxdmg` 若自杀：

- 仍保留在 `plans`，供模型看「伤害上限」；
- 不进入 `best`（除非所有线都死）；
- `ctx.warn` 单独输出 `RISK maxdmg hp<=0：只作伤害上限，不要照打`。

综合评分本来就把 `hp<=0` 打到 `-1_000_000`；P1-2 再加可见标记，避免
模型把伤害上限当安全线。

## 测试

```powershell
python tools/test_plan_visibility.py
```

覆盖：五类计划齐全/药水单列、第 8 张手牌进入 `calc.dmg`、AOE 多目标斩杀、
伤害药水补刀、`maxdmg` 自杀线 `risk` 与警告、搜索时间上限。

## 已知限制

- `maxdmg` 的伤害仍只来自当前手牌与药水，不含随机抽牌收益；抽牌后未知牌的
  执行边界见 [`DRAW_BOUNDARY.md`](DRAW_BOUNDARY.md)。
- `search` 超时后候选可能不是全局最优；这是「响应速度优先」的取舍。
- `lethal_targets` 不模拟抽牌/加牌，也不把「先杀一只触发尸晕再杀另一只」
  的连锁纳入同一个目标的判定；连锁由 `ctx.calc.chain` 单独呈现。
- 药水线只试「药水先手」，不枚举「打两张牌后再喝药」的全部顺序。
