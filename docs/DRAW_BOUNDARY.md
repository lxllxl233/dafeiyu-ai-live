# P1-3：回合协议与抽牌边界

目标：让「抽牌之后手牌变成未知」这件事在工具层显式可见，模型不能把抽牌前的
手牌当成抽牌后的手牌继续排；同时把 `calc.nxdraw` 从“预测”降级为“期望值”。

## 1. 两种合法协议

### 1.1 打到一半：`mid`

不写 `end` 就是只打前半手：

```json
{"say":["先抽一口，看看来什么。"],"seq":[{"c":"POMMEL_STRIKE","t":0}]}
```

返回：

```json
{"ok":true,"mid":1,"next":"read_ctx",
 "mid_reason":"已抽 1 张，手牌已变；先读 ctx 再出下一手，不要按抽牌前的手牌继续排",
 "ctx":{...}}
```

模型必须读返回的 `ctx.hand`，再决定下一手；不能沿用抽牌前的 `ctx.hand`。

### 1.2 打完这回合：`end`

`end` 仍然必须是最后一步，且只出现一次（P0-3）。抽牌后直接 `end` 合法：

```json
{"seq":[{"c":"POMMEL_STRIKE","t":0},{"end":1}]}
```

但抽到的牌可能带回合末状态税（感染/燃烧/剧毒等），本地 `sim` 看不到；此时
`fx.draw_unknown` 会标出抽牌数，`fx_error` 只硬校验能量，`hp/take` 由下一
回合 `ctx` 复核。

## 2. 禁止：抽牌后预排未知牌

以下计划会在 `sim.validate` 阶段被整手拒绝（`ANGER` 不在抽牌前手里）：

```json
{"seq":[{"c":"POMMEL_STRIKE","t":0},{"c":"ANGER","t":0},{"end":1}]}
```

如果 `ANGER` 不在抽牌前手里，错误是：

```text
抽牌边界：第2步 ANGER 不在抽牌前手牌里；前面已抽 1 张，抽到什么由游戏决定，
不能预排。先把抽牌牌单独打出去（不要写 end），读新 ctx 再出下一手
```

`act` 返回 `ok:false`、`next:"split_at_draw"`、`hint`，并且**一张牌都不发**。
不会出现“只打前半手、后面的动作静默丢掉”的情况。

允许的相邻动作：

| 抽牌后下一步 | 是否允许 | 原因 |
|---|---|---|
| `end` | 允许 | 只是结束回合；账本标 `draw_unknown` |
| 抽牌前已经在手里的牌 | 允许 | 这张牌的 id/费用是确定的 |
| 药水 | 允许 | 药水不依赖抽到的手牌 |
| 不在抽牌前手里的牌 | **拒绝** | 抽到什么未知，不能预排 |

## 3. `calc.nxdraw` 是期望值

`ctx.calc.nxdraw` 字段：

| 字段 | 含义 |
|---|---|
| `n` | 预计能抽到几张（抽牌堆+弃牌堆不足 5 时可能 <5） |
| `blk` / `dmg` | 按牌堆组成估的期望格挡/伤害，不是确定值 |
| `pool` | 参与估计的牌数 |
| `mix` | 是否动用了弃牌堆洗牌 |
| `uncertain` | 恒为 `1`：抽牌顺序未知 |
| `why` | 为什么不确定 |
| `short` | 抽牌堆+弃牌堆不足 5 张时为 `1` |

抽牌堆 ≥5：按整堆组成估接下来 5 张；抽牌堆 <5：先拿光抽牌堆，再从弃牌堆
按平均质量补足。两种都不会声称知道牌堆顶是什么。

## 4. 测试

```powershell
python tools/test_draw_boundary.py
```

覆盖：

- 抽牌后写未知牌：`validate` 拒绝、错误带 `抽牌边界`、`act` 零动作；
- 抽牌后打抽牌前已有的牌：允许；
- 只打抽牌牌不写 `end`：执行、`mid:1`、`next:read_ctx`、`mid_reason`；
- 抽牌后直接 `end`：允许，`fx.draw_unknown`，抽牌回合不硬验 `take`；
- `nxdraw` 的 `uncertain/mix/short/why` 与期望值。

## 5. 已知限制

- 只拒绝“不在抽牌前手里”的牌；如果模型把抽牌前已有的牌误当成抽到的牌，仍能
  执行，但打出的牌是确定的，不会打错牌。
- `sim` 不会把抽到的牌加入 `sim.hand`，所以本地 `forecast` 的 `hp/take` 在
  抽牌+end 回合只是近似值；下一回合 `ctx` 才是硬账本。
- `nxdraw` 是按卡牌描述估的期望，不建模遗物/能力/状态牌对抽牌的修正。
- 这是离线协议验证，不等于实机 A10 验证；实机仍以 `ctx` 和账本为准。
