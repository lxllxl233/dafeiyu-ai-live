# P2-1：非战斗评估器（奖励 / 商店 / 营火 / 选牌）

`tools/noncombat.py` 把非战斗界面的**牌组缺口、选项分数、建议**放进
`ctx.choice.eval`。它只做建议，不执行动作：模型仍要结合当前血量、下一节点、
药水和手册做最后决定。

## 1. 为什么不是“自动选”

非战斗决策的代价不在单张牌，而在**牌组变厚后抽不到关键牌**。所以评估器：

- 先算牌组结构（张数、AOE、防御、抽牌、回能、诅咒、升级数）；
- 再按缺口给每张牌/每个选项打分；
- 最后用**牌组越大越高的门槛**决定“可拿/跳过”；
- 所有分数都带 `why`，不把模型变成黑盒的按钮。

## 2. 输出契约

`ctx.choice.eval`：

```json
{
  "deck": {"size": 15, "atk": 6, "skl": 6, "pow": 2, "curse": 0,
            "strike": 3, "defend": 4, "blk": 7, "aoe": 1, "draw": 2,
            "en": 1, "exh": 0, "debuff": 1, "upg": 5, "avgc": 1.1},
  "need": ["aoe", "energy"],
  "mode": "reward",
  "opts": [{"i": 0, "sc": 62, "tag": "aoe", "why": "8伤/1费+14；AOE缺口+18"}],
  "best": 0,
  "skip": false,
  "bar": 42,
  "why": "aoe（62分）≥42：可拿"
}
```

| 字段 | 含义 |
|---|---|
| `deck` | 牌组结构；`blk` 是带格挡的牌数，`aoe/draw/en` 是带该效果的牌数 |
| `need` | 按 A10 手册排的缺口：`aoe > block > draw > energy > attack > trim` |
| `mode` | `reward` / `shop` / `rest` / `select`；选牌另有 `upgrade/remove/transform/copy/choose` |
| `opts` | 每个选项的 `sc`（0–100）、`tag`、`why`；商店项还带 `sec/i` |
| `best` | 分数最高的选项下标；商店为 `{sec,i,sc,why}` 或 `null` |
| `skip` | 奖励/选牌：建议跳过 |
| `buy` | 商店：按分数排序的可买项（最多 3 个） |
| `bar` | 奖励门槛；张数越多门槛越高 |
| `heal` / `up` | 营火：回复量 / 建议升级目标 |

## 3. 分数的来源

### 3.1 牌

```text
基础分（攻38 / 技36 / 能力52）
+ 伤害/费、格挡/费
+ 抽牌、回能
+ AOE（缺口时 +18，否则 +8）
+ 易伤/虚弱
+ 稀有度（Common 0 / Uncommon 4 / Rare 8 / Ancient 10）
- 基础牌 18
- 牌组超过 14 张的厚度惩罚（每张 -2.2，最多 -15）
- 自伤、3 费低效
```

这不是胜率，是**相对排序**。例：0 AOE 的 15 张牌组里，8 伤 AOE 会明显高于
6 伤打击；18 张牌组里两者都会被门槛压到“跳过”。

### 3.2 奖励门槛

| 牌组张数 | `bar` | 行为 |
|---:|---:|---|
| ≤15 | 42 | 补缺口的优质牌可拿 |
| 16–17 | 54 | 只拿明显强于现有牌 |
| ≥18 | 62 | 只拿质变；否则跳过 |

`skip:true` 时 `best` 仍是最高分选项，方便模型看到“最高也只有多少分”。

### 3.3 商店

```text
可买 = 选项可用 且 价格 ≤ 当前金币
分数 = 牌面/资源分 × 0.8 + 20 × 价格效率
```

- 价格 ≤50 金：价格效率 1；越贵越低，150 金以上趋近 0。
- 删牌按牌组张数：≥16 张 70 分，14–15 张 52 分，≤13 张 38 分。
- `buy` 只是候选，不强制清空金币；Boss 前仍按手册“花到 ≤20”。

### 3.4 营火

- 休息分：`40 + 60 × 已损血比例`，低于 70% 再 +15。
- 锻造分：`55`，≥70% 血 +20，<50% 血 -25；没有可升级牌 -40。
- 低血（50%）示例：休息 85，锻造 63；满血：休息 40，锻造 83。
- `up` 给建议升级目标（痛击/耸肩/坚毅/剑柄/全身撞击等优先）。

### 3.5 选牌 / 升级目标

- 从 `selection.prompt` 识别 `upgrade/remove/transform/copy`。
- 升级：`card_eval + 牌名优先级`；打防不优先。
- 删除/变化：按“牌面越弱越该删”，基础打击最高，核心牌大幅降分。
- 复制：优质牌 +10；其余按牌面分。

## 4. 明确不做什么

- **不替代路线**：地图仍走 P0-2 `route` / `path.py`；`eval` 不评估 map。
- **不评估事件文本**：事件选项的长期代价（诅咒/最大生命/遗物）无法只靠关键词量化，
  仍按 `ctx.choice` 原文和手册判断。
- **不预测遗物/能力联动**：分数只看牌面与牌组结构；“腐化+无惧”这类 combo
  需要模型自己加权。
- **不是胜率**：没有实机 A10 样本校准前，不声称 `sc` 等于胜率提升。

## 6. 后续校准

实机 run 复盘时，把 `eval.best/skip/buy` 与模型实际选择、后续掉血一起记在
`logs/run*_review.md`；P3-1 本轮只做终局评估，非战斗选择仍未结构化落账，后续需要再加。

重点核对：

- `skip:true` 后是否真的因牌组太厚输；
- `best` 与模型实际选择不一致的局，记录原因；
- 商店 `buy` 是否挤掉删牌/药水；
- 营火 `best` 与后续掉血是否相关。

没有这些样本前，只把 `eval` 当**排序提示**，不当硬规则。
