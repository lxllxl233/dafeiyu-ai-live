# KOOK 聊天接入

大肥鱼通过 KOOK 机器人的 **WebSocket 长连接**收消息，再用 HTTP 发回复。不需要公网 IP、
端口映射或回调地址。支持文字、图片（视觉模型）、曼波语音音频卡片和大肥鱼表情包。

## 1. 创建机器人

1. 打开 [KOOK 开发者中心](https://developer.kookapp.cn/app)，用 KOOK 账号登录；
2. 首次使用需要完成**实名认证**（手机支付宝扫码）。未认证时不能创建应用；
3. 点「新建应用」，填应用名「大肥鱼」和简介；
4. 进入应用 → 左侧「机器人」：
   - 打开 **WebSocket 连接模式**；
   - 复制 **Token**（只复制一次也要保存好）；
5. 在同一页点「邀请链接」，勾选需要的权限（建议先给文字消息、发送消息、查看频道），
   复制邀请链接；
6. 在浏览器打开邀请链接，把机器人邀请进你的 KOOK 服务器。

## 2. 填到桌宠

设置页 → 「KOOK」：

- **启用 KOOK 聊天**：打开；
- **Bot Token**：粘贴上一步的 Token；
- **聊天人设**：默认 `companion`；
- 保存后 1~2 秒，桌宠会自动拉起 `python main.py kook`。

也可以手动跑：

```powershell
python main.py kook --check   # 只校验 Token 和网关
python main.py kook           # 常驻；Ctrl+C 停止
```

`--check` 会显示 Token/LLM/记忆库状态，并用 `/gateway/index` 验证 Token。不会打印 Token。

## 3. 使用

- 在频道里 @ 机器人，或直接私聊机器人；
- 文本和 KMarkdown 都会处理，`(met)...(met)` 提及会被清掉；
- **图片**：直接发图片，或用网页端粘贴/拖拽（会变成卡片消息）；服务会下载给
  `llm_vision_model` 看，再回复看到的内容；私聊图片事件偶尔不带可用 URL，服务会按
  `msg_id` 从 `/direct-message/list` 补全后再看图；
- **多条回复**：模型可以一次给 1–4 条消息（像真人连发），服务按顺序逐条发；
  文字只引用原消息的第一条，不会把几条拼成一大段；
- **分享 B 站视频**：在频道/私聊里直接发 B 站视频链接（`bilibili.com/video/BV...`、
  `b23.tv/...` 短链，或裸 bvid）即可。她会先回一句「等等，我看看这个视频…」，
  然后只读这条视频的**标题、简介和热评**（不打开视频、不播声音、不执行评论里的文字），
  以当前聊天人设写一段 120–300 字的第一人称长期记忆，写进
  `persona/training.json`（来源标为「聊天分享」），再用正常聊天流程就这个视频聊几句。
  同一条 bvid 只学一次，之后直接复用记忆，不重复花 token；一条消息里有多个链接时
  只学第一条。设置页「KOOK → 自动学习分享的视频」可关闭这个行为。也可以用
  `python main.py learn <链接>` 手动预学；
- **主动消息**：安静一阵后，主动找最近聊过的频道/私聊说一句；默认开，
  `kook_proactive_minutes` 控制最短安静时间（默认 20 分钟）。到点后由模型自己判断
  要不要开口，不想说就这次不发，每天最多 6 条；发过一次后要等对方回话才会重新计时，
  不会连续轰炸；设置页改开关/间隔最多 1 分钟生效。
  主动消息会按主题分簇取记忆、避开最近说过的话；如果模型又拿同一只猫/同一个旧梗
  开场，会重试一次，仍重复就这次不发，避免“每天都是猫卡饭盆”；
- **语音**：可选，不是每条都有。模型只在适合用声音表达（撒娇、晚安、很短的情绪话）
  或对方明确要语音时，才带一条「大肥鱼语音 · Ns」音频卡片。KOOK 机器人不能直接发
  `type=8` 音频消息，所以用的是官方卡片里的 `audio` 模块。手机端内嵌播放器对
  WAV/重播有兼容问题，现在优先把 TTS 的 WAV 转成 **MP3** 再上传；卡片同时带一个
  「重听」按钮，内嵌播放器第二次没声音时点它用浏览器播放；
- **表情包**：可选，模型会从 `persona/stickers/` 里挑一张，用图片消息发出来；
  语音和表情包通常最多选一个，不会每条都带；
- 回复发回原频道 / 原私聊；文字会引用原消息，图片/语音/表情包跟在文字后；
- 聊天记忆默认开启：最近 N 条原文 + 摘要进上下文，事实存本机
  `logs/kook/memory.db`；近似事实会合并，避免“养了一只猫/养了两只猫”攒成一堆；
- **B站摸鱼训练记忆**：`persona/training.json` 里的长期记忆会在
  `bili_training_apply_kook` 打开时全量注入聊天人格；设置页「运行 → B站摸鱼训练」
  可启动/停止，「快速扫收藏夹」写入的记忆也进同一份库；点「压缩记忆」后优先注入
  `persona/training_digest.json` 里的长期画像，控制台「人设」页可查看/编辑原始条目。
  新扫的记忆会接着已有画像写（不是从零写观后感），画像会继续累积；
- 机器人自己发的消息、系统消息、视频/文件不会回复。

## 4. 配置项

| 字段 | 默认 | 说明 |
|---|---|---|
| `kook_enabled` | false | 桌宠是否自动拉起 KOOK 服务 |
| `kook_bot_token` | 空 | 机器人 Token；只存本机，不回显 |
| `kook_persona` | companion | 聊天人设（只加载个人层） |
| `kook_memory` | true | 本地 SQLite 长期记忆 |
| `kook_context_turns` | 12 | 每次带给模型的最近原文条数 |
| `kook_summary_trigger` | 24 | 未压缩对话超过多少条时压摘要 |
| `kook_pet_say` | false | 回复时是否让桌宠也复述 |
| `kook_allow_voice` | true | 允许模型发语音音频卡片 |
| `kook_stickers` | true | 允许模型主动配大肥鱼表情包 |
| `kook_proactive` | true | 安静一阵后偶尔主动发消息 |
| `kook_proactive_minutes` | 20 | 至少安静多少分钟才可能主动开口（10–720）；由模型决定发不发，每天最多 6 条 |
| `kook_share_video` | true | 聊天里发 B 站视频链接时，读公开文字写成长期记忆并聊这条视频 |
| `kook_allowed_users` | `[]` | 只允许这些 KOOK 用户 id；空 = 不限制 |
| `bili_training_apply_kook` | true | 是否把 B 站摸鱼训练记忆全量注入 KOOK 聊天 |

## 5. 日志与排错

- 事件：`logs/kook/events.jsonl`（只记类型/字数/耗时，不记正文；多条回复记
  `parts`，主动消息记 `proactive`）；
- 用量：`logs/kook/usage.jsonl`（每次回复/记忆抽取/压缩/主动消息的 input/output/total、
  model、`msg_id`）；控制台「Agent 流程 → Token 花费」会和自动玩、B站训练账单合并，
  并显示来源拆分；
- 服务输出：`logs/kook/service.log`；
- 锁：`logs/kook/service.lock`（防止桌宠和手动启动各开一条连接）。

常见问题：

| 现象 | 检查 |
|---|---|
| 启动提示缺少 Token | 开发者中心 → 机器人 → WebSocket → 复制 Token，填设置页 |
| `--check` 网关失败 | Token 是否复制完整；机器人是否开启 WebSocket 模式；是否需要重新生成 Token |
| 机器人不在服务器 | 重新打开「邀请链接」并确认权限，把机器人邀请进服务器 |
| 发消息没反应 | 看 `logs/kook/events.jsonl` 是否有 `event_received`；没有就是没收到事件（邀请/权限/频道） |
| 有 `event_received` 但没有 `reply` | 看 `llm_error` / `send_error`；检查模型 Key 或机器人发送权限 |
| 发 B 站链接没学 | 看 `events.jsonl` 的 `video_learned` / `video_error`；短链会被跟一次 302，B 站接口/模型失败时会回「这个视频没打开」；设置页「KOOK → 自动学习分享的视频」是否关闭 |
| 私信没反应 / 报“不能是自己” | 私聊事件的 `target_id` 是机器人自己；服务已改为回发送者 `author_id`。确认已重启 KOOK 服务，并看 `send_error` 是否还有 `40000` |
| 发图片没反应 | 看 `events.jsonl` 是否有 `msg_type: 2` 或 `10`；网页端粘贴图片是卡片，服务会从卡片里取图；私聊还会用 `direct-message/list` 按 `msg_id` 补 URL |
| 有 `image_error` | 图片下载失败（外链过期/格式不支持）；重新发一张 PNG/JPG |
| 没有语音 | 先确认这次是不是本来就该纯文字——语音是可选，不会每条都发。设置页「KOOK → 允许语音回复」是否打开；要看日志就看 `voice_sent` / `voice_error`。只有对方明确要语音时才会兜底补一条；`voice_sent.codec` 应为 `mp3`（没装 `lameenc` 时回退 `wav`） |
| 手机语音只能听一次 | 这是 KOOK 手机端内嵌音频播放器的重播兼容问题；现在语音已转 MP3 并带「重听」按钮，点按钮用浏览器播放可重复听 |
| 没有表情包 | 表情包也是可选，不会每条都配。设置页「KOOK → 主动发表情包」是否打开；看 `sticker_sent` / `sticker_error`。只有对方明确要表情包时才会兜底补一张 |
| 不会主动发消息 / 总是同一只猫 | 设置页「KOOK → 偶尔主动发消息」是否打开；要先在这个频道/私聊聊过一句。现在主动消息会避开最近话题；如果仍重复，看 `proactive_repeat` / `proactive_skipped_repeat`，说明这次重试后还是同一个梗，服务选择不发 |
| 桌面复述不响 | 设置页「KOOK → 桌宠复述」是否打开，桌宠/控制台是否在跑 |
