> 铁甲 skill 是**只读基线**：不改它的规则、不删它的教训。

## 0. 传输协议（v20：ctx → act，一回合两次调用）

```powershell
python tools/ctx.py --out tmp_ctx.json     # 局面包：手牌实费/效果、抽弃消耗堆、遗物、药水、双方 buff、每怪当前与下次意图、球(orbs)、斩杀线
# 读 tmp_ctx.json → 写 tmp_plan.json（UTF-8）：
# {"say":["它 16，电击加双发刚好带走。","这回合没人打我。"],
#  "seq":[{"c":"ZAP"},{"c":"DUALCAST","t":0},{"end":1}]}
python tools/act.py --file tmp_plan.json   # 执行并把下一回合局面包一起回给你
```

- `c` 写 card_id（`ZAP` / `COOLHEADED` / `SUNDER`；升级写 `ZAP+`），**不写手牌下标**；`t` 敌人下标（可省，默认打威胁最大的活怪；AOE 不写）
- `p` 药水槽（有目标必须给 `t`）；`end` 必须是最后一步；不写 `end` = 打到一半停（等抽牌/Buff 落地）
- `say` 1–3 句：第一句本回合播，其余排队
- 旧协议 `tools/turn.py`（`sts2 batch` 短写法）仍可用，但 v20 起**默认 ctx/act**

## 1. 机器人 A0 的七步（每回合照做）

```
1 ANCHOR（入伤/能量/手牌）+ 敌人意图 + 现有球（ORBS）
2 一句机制：这一回合是「铺球」「激发」「转甲」还是「斩杀」
3 算账：本回合总伤 = 攻击牌 + 闪电球被动(3+集中) × 球数 + 激发伤害
       本回合总甲 = 格挡牌 + 冰霜球被动(2+集中) × 球数 + 激发甲
4 定回合类型：斩杀 / 入伤≥HP 全挡或喝药 / ≤10% 最大生命挡满 / 其他吃甲换血
5 出牌顺序：0 费/抽牌 → 集中（同步/热修复）→ 铺球 → 激发 → 攻击收尾
6 一条 batch 出完
7 收尾三查：能量=0/N、能打的格挡牌没有、0 费牌没有
```

## 2. 球与集中（机器人的硬机制）

| 球 | 被动（回合末） | 激发 |
|---|---|---|
| 闪电 Lightning | 3 + 集中 伤，随机敌 | 16 + 集中 伤，随机敌 |
| 冰霜 Frost | 2 + 集中 甲 | 5 + 集中 甲 |
| 黑暗 Dark | 蓄能（下回合爆） | 6 + 蓄能 伤 |
| 等离子 Plasma | +1 能量 | +2 能量 |

- **集中**先于一切：+2 集中 = 每一颗闪电 +2 伤、每一颗冰霜 +2 甲，一局能翻倍两次。
- **冰霜球就是防御牌**：铺满 3 颗冰霜 + 2 集中 = 每回合白嫖 15 甲，比任何防御牌都稳。
- **激发要看时机**：`双发` 激发一颗（闪电 16 伤 = 前期最大爆发）；`打碎` 激发全部两次（一波清场）。
- 球位上限默认 3：先铺满再激发，别一颗一颗浪费。
- **A0 节奏**：允许先铺两回合再输出，血量 70%+ 时不要为了“稳”每回合全防。

## 3. A0 与 A10 的差别（我踩过的坑）

- A0 没有「进阶之灾」诅咒、精英密度低、敌人伤害低约 20–30% → 可以**先建立引擎再谈输出**。
- 但 **A0 的牌组膨胀同样致命**：>20 张时抽不到关键牌。每幕至少删 1 张、只拿质变牌。
- 机器人最怕的不是掉血，是**抽不到球/集中** → 优先拿「抽 1 张」的牌（冷静头脑、扫荡射线、刮削）。

## 4. 说话（在 sts2-caster 之上）

- 密度 **40%–75%**（`MEME_BAR`），每 2–3 个动作一条；长度 ≤60 字。
- **时不时来一句「鸡煲」笑话**（每 6–10 个动作一次，别连刷）。「鸡煲」= 故障机器人（社区通用外号，已核实）：
  - 起手/终于铺好球：「我已启动。」（鸡煲的招牌，前面要有本回合的真实启动事实）
  - 还没启动时：「还没启动。」／「通电、开机、找集中、找冰球——四件事。」
  - 强度自嘲：「鸡煲是尖塔第四强的角色。」（一共四个角色）
  - 「偏差认知」梗（每回合掉集中）→ 句子逐行递减：「这波还能打／这波还能／这波还／这波／这」
  - 「回响形态」梗（第一张牌触发两次）→ 同一句复读两遍：「稳了稳了。」
  - 小红（打技能牌加力量）：「鸡煲的严父又来了。」
  - 暴毙：「上把暴毙一层中，这把美滋滋白嫖，全是小怪……」
  - 宁可少说，也别编不是社区的梗。
- 梗放句尾，一句一个，不解释。

## 7. 实战教训（run1：A0 死在第二幕 33 层 Knowledge Demon）

- **死因链**：第一幕 Boss 13 血险胜 → 第二幕一路低血（22/15/10）靠营火续 → 27 张牌里只有 5–6 张格挡牌 → Boss `8×3=24`、`10×3=30` 挡不住。
- **牌组别过 22 张**：run1 拿了 27 张，打击/防御混在里面，抽不到 Loop/冰球。第二幕起拿牌前先问「比删一张基础打击强吗」，答不上就跳过；营地优先锻造/删牌而不是见牌就拿。
- **格挡密度是硬门槛**：进第二幕前格挡牌 ≥8 张，或至少 2 张高甲（飞跃/充电/究极防御）。第二幕敌人单体 20–30 伤是常态。
- **本版强势核心**：`注能核心`（开局 3 闪电、闪电 +1 伤）+ `符文电容器`（+3 球位）+ 双 `循环`。三件凑齐后每回合白嫖 12–18 伤。见到「欧洛巴斯之触」优先换核心；商店 `符文电容器` ≤200 必买。
- **饥饿（噬尸蛞蝓）**：杀一只会触发另一只「吃尸体眩晕」——集火先杀一只等于白赚一回合，比平均输出强。
- **无实体回合别输出**：只挡+铺引擎。`抱抱先生`（按回合数群伤）配慢速球流很稳。
- **Boss 三选一诅咒**（瓦解 6/7 血每回合 / 心灵腐化少抽 1 / 懒惰最多 3 张）：低血优先选「懒惰」或「心灵腐化」，别选瓦解。

## 8. 弹幕/配音链路（改过就别再踩）

- 一回合**只推一条**弹幕，并且在**出牌之前**推（`cmd_batch` / `cmd_do` 都是先 say 再 act）。
- 页面主通道是 **SSE** `/events`（实测 1ms 到达），别退回 350ms 轮询。
- 浏览器源音频比画面晚 ~90–150ms：前端用 `SPEAK_LEAD_MS`（默认 100）把弹窗延后对齐；抖动时长 = `buf.duration`（说多久抖多久）。
- 排查工具：`/mark?ev=bubble`（页面自报渲染时刻）+ OBS `InputVolumeMeters`（声音进混音时刻），两者相减就是真实音画差。
