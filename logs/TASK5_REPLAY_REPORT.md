用账本里 2092 条历史决策的**原始局面**做了离线回放，四个指标都能量出来：

**胜率不可比较**：mod 没在跑（`ConnectionRefusedError 10061`），一局新的都没跑。

1. **`tools/replay_audit.py`**（新，593 行）：不做假设，直接读 `logs/decisions.jsonl` 里每行携带的
   `state`（决策当时的**原始** `/state`，不是摘要）重建局面，再跑四个测量。
2. **账本补 `input.allow`**：`decision_log.record_decision` 增 `allow`（`tools/decision_log.py:349,378`），

   不补这个，「历史执行、今天被拦」永远分不清是**护栏漏了**还是**模型显式豁免**（run98 22:10:15 就是这种）。
3. **自伤闸落到计划层**：`ctx` 的 `plans[]` 增 `self/self_why`，`warn` 增 `SELF_HP`
   （`tools/ctx.py:100,103,693,748`）。只**标注冲突**、不重排计划——重排会藏掉「唯一能打的线」。
4. **测试**：`tools/test_replay_audit.py`（48 项，判定函数用**手写反例**证否）、

   `tools/test_docs_consistency.py` 加 13 项（文档/工具/产物同源，误拒/放行必须为 0）。

## 2. 方法（以及为什么这些数字能回到具体时刻）

账本每行自带 `state`（手牌实费、敌人意图、遗物、药水、地图节点）、`steps`、`forecast`、
`before/after` 两帧摘要、`outcome`。所以：

| 指标 | 口径 | 代码 |
|---|---|---|
| 规则命中率 | 注入条数/行（必须 5.0）；条件触发=把规则文字翻成谓词，违规数/触发数 | `replay_audit.py:147-215` |
| 无效动作 | `outcome != executed`，按局拆到具体拦截层 | `replay_audit.py:373-489` |
| 执行器状态不一致 | `forecast` 当时的预测 vs `after` 实际；跳过 `clear/approx/revive/tick/draw_unknown/heal`；分 `conservative`（预测更惨，安全）/`optimistic`（预测更好，危险）/`death`/`death_missed` | `replay_audit.py:257` |
| 决策违规率 | 触发且违反 / 触发 | 同上 |
| 护栏回归 | 用今天的 `validate_plan`+`forecast`+`_guards`+`fx_error` 重跑同一 `seq` | `replay_audit.py:218` |

规则谓词是**审计侧对规则文字的翻译**，不是引擎行为——所以 `docs/REPLAY_AUDIT.md` 里逐条写清了
触发/违反公式，改规则文字必须同步改这些函数（测试会失败）。

## 4. 回归结论（这才是任务 5 的核心）

```
历史执行今天被拒：0        ← 今天的校验没有误伤任何一条历史正常牌序
历史被拒今天全放行：0      ← 历史上被拦的，今天仍然拦
护栏保持：guard 15/15、fx 33/33
今天新拦：0（guard 0 / fx 0）
allow 未入账的疑漏：9 行
```

- **0 误伤**是关键：`act.validate_plan` 换过、`sim` 改过、`hard_rules` 加过，如果校验变严了，
  历史能执行的牌序今天会被拒——一条都没有。
- **9 条"疑漏"**是「历史执行了、今天 `_guards` 会拦、但老账本没记 `allow`」。逐条看过（如 run98 22:10:15
  `end` 留 5 费），都是模型当时显式带了 `allow_leftover` 一类豁免——**但账本没记，所以不能写成"护栏漏了"**。
  这条不确定性已经用 `input.allow` 消掉，下一季可精确判定。

## 5. 新发现：规则到了眼前，但没进计划打分

`--plans` 在本赛季「≤40% 血 + 手握自伤牌」的 23 行上，用今天的 `ctx` 重算推荐线：

```
23 行可比：18 行的推荐线仍含自伤牌（12 行没有别的线，6 行本来有不自伤的替代线）
```

6 条「有替代线却仍把自伤牌排在 `best`」：run97 21:44:23（15% 血）、run104 23:42:07（40%）、
run105 23:49:29 / 23:49:38（8%）、23:49:47 / 23:50:12（4%）——全是 `BLOOD_WALL`。

run105 的复现：23:49:29 局面 hp 6、能量 3、手牌含血墙/防御；今天 `sim.search` 的 `best` 仍是
`BLOOD_WALL → DEFEND`，预测 hp 3。历史真的就这么打了：6→3（23:49:38）→1（23:50:12）→0（23:51:14）。
**规则写了"血≤40% 不交自伤牌"，模型也读到了，但 `best` 线在推荐它。**

处置（保守，不替你改策略）：`plans[]` 加 `self=1` + `self_why`（"血6/80（8%）交BLOOD_WALL会自扣血"），
`warn` 加 `SELF_HP` 一行，测试锁死「只在 ≤40% 血出现」。**没有偷偷重排**——
12 行里血墙是唯一的格挡线，重排会引导模型去送死。
真正的修法在 `sim` 打分（给自伤牌加罚分），那是策略层改动，留作下一步。
